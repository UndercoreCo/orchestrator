# Linux-приёмка автономного разрешения: 26.10.2026

Проверка кандидатов без выпуска и без изменения рабочих служб.
Controller: `1b74d1388e3697061ac7cf7074e080f4355b7e62` (PR #16).
AWG-agent: `df9a12f0a71e516ae056d550f9096940e069ac15` (WG PR #2).

## Окружение и границы

Отдельные временные контейнеры сервера и клиента на существующем Linux-хосте:
`uc-offline-server-20261026`, `uc-offline-client-20261026`. Внутренняя Docker-сеть
не публикует UDP/TCP-порты. У контейнеров нет host network, privileged или Docker
socket; только NET_ADMIN/NET_RAW и TUN, read-only rootfs, ограниченные RAM/CPU/PID.
Движок взят из уже установленного образа по точному image ID, не по latest.

Runtime, state agent и HTTPS запущены отдельными временными systemd units,
производными от исходных templates. Различаются имена, пути, UID/GID, loopback
порт 19876 и имя dedicated контейнера. Методы backend и алгоритмы исходников
не менялись. State/API используют отдельных временных пользователей без shell;
исходные ограничения systemd сохранены. У runtime остаётся Docker authority.

Controller использует настоящий HTTPX transport с отдельным проверяемым CA
стенда; это не MockTransport и не отключение TLS validation. Каждая команда
запускается отдельным процессом Python 3.12, читая тот же SQLite журнал.
Тестовые профили и ключи генерируются только на стенде и не копируются в Git.
Автоматический таймер уборки ограничивает срок жизни ресурсов.

Трафик проверяется ICMP через реальный userspace AmneziaWG между двумя network
namespaces. Проверены настоящие системные таймеры, Unix credentials и systemd.
Это не проверка публичного интернета, DNS, клиентского macOS/iOS приложения,
межсерверной задержки, полного отказа хоста или TrustTunnel.

## Результаты

- Linux/Python 3.12: 121 тест агента пройден, пропусков нет; тестовый контейнер
  не имел сети, Docker socket и production-файлов.
- При выключенном HTTPS API существующий туннель пережил короткий срок lease;
  через 120 секунд тестовый трафик шёл, а peer с истёкшим сроком был удалён.
- Readiness controller стала false. Создание нового доступа без свежего lease
  вернуло `control_lease_expired` без добавления записи.
- Восстановление controller сохранило конфигурацию побайтно.
- Disable не отменяется следующим heartbeat.

После disable/enable первый короткий ping не прошёл; последующий прошёл без
смены клиентской конфигурации. Сценарии после полного удаления peer допускают
ограниченное время на повторный handshake. Это отличается от непрерывной работы
при потере управления, где peer остаётся на месте. Первичный неуспешный probe
сохранён в отчёте; не выдаём его за непрерывный успешный прогон.

## Завершение приёмки

После первичного probe проверки продолжены с ограниченным ожиданием handshake:

- После 320 секунд без новых разрешений (offline policy 300 секунд) реальный
  туннель закрыт; peer удалён. Возврат управления восстановил тот же конфиг.
- Перезапуск state/runtime без новой sequence оставил доступ закрытым;
  новый heartbeat восстановил прежнюю конфигурацию.
- При SIGSTOP state-agent независимый watchdog удалил peers; проверка через
  105 секунд подтвердила отсутствие трафика. Production-службы не останавливались.

После аварийной смены адресов возобновлён только незавершённый сценарий отката
на заново созданном изолированном стенде. Выполнен реальный переход процессов
controller 0.6.0 / agent 1.1.0 → controller 0.5.3 / agent 1.0.0 → новые версии.
Внутри сценария использовалась одна текущая SQLite-база, без восстановления
старого журнала. Подтверждено:

- старый агент запускается с закрытым доступом до нового разрешения;
- старый controller отвергает новый ключ настроек, прежние настройки принимает;
- запрет, identity и сохранённое окно fencing 425 секунд переживают откат;
- только явный enable возвращает трафик; экспорт конфигурации совпадает побайтно;
- повторное обновление сохраняет тот же конфиг, identity и окно fencing.

Все пять проверок rollback завершены успешно за 128,7 секунды. Временные
systemd units, контейнеры, сеть, пользователи, состояния и секреты удалены.
Сравнение до/после подтвердило неизменность ID, времени старта и образов рабочих
контейнеров, а также набора peers рабочего AmneziaWG.

Обезличенные отчёты сохранены в локальной рабочей папке
`diagnostics/20261026-orchestrator-acceptance/`: `acceptance-result.json`,
`acceptance-first-attempt.json`, `rollback-result.json`, `cleanup-result.json`
и `unit-tests.log`. Первичный неуспешный probe не удалён из доказательств.

## Статус перед выпуском

У согласованного Linux-сценария больше нет незавершённых проверок. Это не
подтверждение reboot хоста, публичной связности, полного отказа source-узла
или поддержки автономного разрешения TrustTunnel.

На 26.10.2026 GitHub CI controller PR #16 прошёл на Python 3.12–3.14,
security и сборка документации успешны. В WG PR #2 задания GitHub не стартовали:
аннотация сообщает об ошибке оплаты или лимите расходов аккаунта (steps пусты).
Это не успешный CI агента; отдельный Linux-прогон 121 теста сохранён выше.

Исходники кандидатов не менялись. Merge, теги, публичный выпуск и production
обновление не выполнялись. Перед выпуском остаются финальное ревью двух PR,
разрешение ограничения GitHub CI агента и согласование поэтапного развёртывания.
