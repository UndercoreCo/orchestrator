# Ограниченная автономность: кандидат для ревью 0.6.0

Продолжение PR #15 и задачи #8. Публикация исходников на ревью согласована;
выпуска и развёртывания в production нет.
Изменён реальный исходник AWG-агента в отдельной рабочей копии WG, затем из него
собрана отдельная тестовая копия. Прежний pinned v1 fixture не изменялся.

## Контракт

- Controller: `policy.leases.offline_duration_seconds`, по умолчанию 0; включение
  допускает 300–3600 секунд от последнего принятого разрешения, не от потери сети.
- Агент сохраняет v1 `control_lease.version=1` и объявляет supported_versions [1,2],
  max_offline_seconds 3600. Новый запрос на /v1/control-lease содержит version 2,
  controller_id, sequence, короткий valid_until и отдельный offline_until.
- Отсутствующая/неправильная capability останавливает выдачу до нового grant.
  Ответ обязан подтвердить точные параметры, fresh и active; потерянный или
  неполный ответ не отменяет уже сохранённую защитную границу.
- Freshness нужна для create/renew/replace/enable. После её потери разрешены
  обслуживание прежних peer, чтение и отзыв, но не новые/продлённые права.
- Runtime получает минимум пользовательского срока и автономного срока.
  Монотонные часы ограничивают оба; повтор команды не продлевает срок.
  Полученный disable сохраняется при новом heartbeat и перезапуске.
- Максимальное окно ожидания сохраняется в схеме 2 до HTTP:
  max(max_node_lease_seconds, offline_duration_seconds) + fence_grace_seconds.
  Уменьшение политики не уменьшает ранее записанное окно. Fresh valid_until
  в controller не заменяется длинным offline_until: readiness остаётся короткой.
- При подтверждённом revoke ожидание не нужно. При недоступном source — полный
  сохранённый срок, затем очистка старой привязки перед повторным открытием узла.

## Агент и совместимость

Кандидат agent API 1.1.0. Старые команды v1 остаются прежними; расширение хранится
в отдельной control_offline, исходная control_lease не меняет layout. Новая v1
sequence удаляет автономное разрешение, старая sequence не меняет режим.
Старый агент после возврата закрывается и не использует длинный срок.
Согласованные HTTP и state-agent должны обновляться вместе; смешанную пару
компонентов не объявляем поддерживаемой. Привилегированный runtime не менялся.

Автономность сохраняется при отсутствии связи с controller, пока state-agent
и runtime работают. Перезапуск state-agent закрывает оба допуска до новой sequence;
replay не открывает их. Это намеренное ограничение данного этапа. Root watchdog
остаётся 90 секунд и не подменяется автономным разрешением. Реальные systemd,
Docker restart, сдвиг часов ОС и маршруты требуют Linux-приёмки.

Новый ключ настроек не понимается 0.5.3. Первое обновление выполняется со старым
файлом settings; включение следует только после успешного обновления. Перед
ручным возвратом к старому controller удалить этот ключ, сохранив текущую базу
и окно fencing. Автоматический updater не допускает понижение версии. Нельзя
восстанавливать старую SQLite поверх актуальных запретов.

## Проверки

- Реальный агент с тестовым VPN backend: работа после 90 секунд до offline_until,
  отказ новых прав без записи в БД, оплаченный срок раньше разрешения, disable,
  возврат времени, повтор и смена режима, закрытие при рестарте, HTTP/OpenAPI.
- Controller + HTTP + кандидат агента: потеря API, восстановление без замены
  identity, потерянный ответ длинного grant, уменьшение политики и рестарт
  controller, полный fencing, revoke во время разделения, очистка source,
  немедленный перенос при подтверждённом revoke, отказ старого агента.
- Обе закреплённые старые копии (агент v1 и storage bridge) сохранены.
  Candidate fixture закреплён на commit df9a12f0a71e516ae056d550f9096940e069ac15
  из [WG PR #2](https://github.com/gatinrustam/wg/pull/2); все 8 файлов сверены
  побайтно с git show. Это исходник кандидата для ревью, не выпущенный агент.

Итог: 437 тестов controller и 117 тестов агента прошли на macOS/Python 3.14.
Четыре Linux/root теста пропущены; Docker daemon недоступен. Ruff/mypy,
контракты, архитектура, workflow-policy, secret scan и сборка 23 публичных
страниц прошли. Это локальные результаты, GitHub CI кандидата не запускался.

## Следующие условия выпуска

Завершить ревью исходников агента и controller.
Проверить Linux/root acceptance, остановку/перезапуск компонентов, реальное
истечение на выделенном VPN-контейнере, rollback с новым ключом настроек,
недоступность controller и недоступность source как разные сценарии.
TrustTunnel не получает эту возможность автоматически. Резерв управления,
сертификаты и самостоятельная поставка adapters/ остаются следующими задачами.
