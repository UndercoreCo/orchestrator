# План завершения Orchestrator 1.0

Согласованное направление от 26.10.2026. Реализация пунктов не означает публикацию
или развёртывание. Текущие возможности перечислены в [матрице](support.md).

Уже есть отдельный controller, слои domain/application/interfaces/infrastructure,
API v2/OpenAPI, CLI/панель, SQLite, наблюдаемость, лимиты операций, backup/update,
рабочий AWG-драйвер и экспериментальный TrustTunnel. Их не требуется создавать заново.

| Этап | Результат | Условие завершения |
| --- | --- | --- |
| 0. Исходники и выпуски | Основная публичная ветка соответствует выпускам, документация честно описывает статус, одна цепочка публикации | Архив совпадает с тегом, происхождение проверяется, повтор публикации не меняет байты |
| 1. Устойчивость | Ограниченная автономность узла, безопасный перенос, резерв управления, сертификаты | Потеря связи/ответа, reboot, expiry и отзыв проверены без дублирующих доступов |
| 2. Адаптеры | Отдельные самостоятельные пакеты AWG и TrustTunnel в adapters/ того же репозитория | Независимая сборка и установка, общий контракт и реальные lifecycle-тесты |
| 3. API интегратора | Полная документация v2, ошибки/повторы, отдельные ключи и namespaces | Два backend изолированы при совпадающих device_id, прежняя интеграция совместима |
| 4. Установка | Публичный релиз + конфиг, проверка окружения, безопасный повтор | Чистые поддерживаемые VM, без внутренних deploy-скриптов и ручной правки исходников |
| 5. Версии/обновления | SemVer компонентов, stable/beta, manifest совместимости, проверяемый updater | Обновление и отказ на его этапах сохраняют ключи/запреты/журнал, откат безопасен |
| 6. Приёмка | Документация внешнего разработчика, нагрузка, длительный стенд, восстановление | Фиксированная матрица пройдена, блокирующих дефектов нет, опубликован 1.0.0 |

## Архитектурная граница

Backend заказчика проверяет пользователя, оплату, слот и срок. Controller выбирает
узел и ведёт технические операции. Адаптер/агент исполняет VPN, сроки и отзыв,
выбирает формат конфигурации; учёт трафика остаётся на узле. Бизнес-квоты не входят
в controller. Панель и CLI не требуют сайта Undercore.

Целевая поставка: orchestrator/, adapters/amneziawg/, adapters/trusttunnel/,
contracts/, packaging/, examples/, tests/ и docs/public/. У адаптеров отдельные
версии, зависимости, настройки, службы и тесты. Агент и адаптер могут быть одной
службой узла; дополнительный прокси только ради структуры не нужен. Текущий
NodeDriver служит основой миграции; ядро не импортирует runtime адаптера.

## Устойчивость: обязательный компромисс

Срок права на доступ, свежесть управляющей связи и условия безопасного переноса
нужно разделить. Автономный узел не продлевает права и сохраняет подтверждённые
запреты. Если старый peer разрешено обслуживать без controller, нельзя считать
его закрытым по прежнему короткому lease и выдавать второй на другом узле.
Перенос ждёт подтверждённого отзыва или истечения всего автономного разрешения.
Длительность автономности и задержка отзыва требуют явной политики и испытаний;
выключение leases не считается завершением этого этапа.

В отдельной ветке подготовлен переходный кандидат 0.5.2: он сохраняет схему 1
и уже умеет безопасно обслуживать схему 2 после отката с будущего выпуска.
Установщик проверен на сценариях отказа с сохранением новых записей журнала;
службы ОС и будущий выпуск в этих тестах имитируются. Кандидат не опубликован.
Он не увеличивает автономность узла: протокол v1 по-прежнему использует короткое
разрешение. Далее нужны активация схемы 2, новый протокол автономного разрешения,
реализация агента и испытания разрыва управляющей сети. Этап 1 остаётся открытым.

## Установка и обновление

Три отдельные операции: установка controller, установка adapter+VPN на сервере,
регистрация готового узла. add server сегодня выполняет только третью.
SSH/root для установки не становится полномочием runtime API выдачи подключений.
Начальная цель приёмки — Ubuntu 24.04 LTS, amd64, systemd; другие окружения
объявляются поддерживаемыми после проверки.

Обновления устанавливают опубликованные проверенные релизы, не каждый коммит main.
По умолчанию применение явное; автоматическое применение — opt-in политика.
Версии программы, API, схемы БД, настроек и документов туннеля различаются.

## Границы 1.0

Обязательны backup/restore со сверкой узлов, ротация ключей и сертификатов,
происхождение артефактов, лицензии, понятные ошибки, наблюдаемость и тестовый адаптер.
Доменные экспорты не обновляют уже импортированный статический файл автоматически;
миграция старых файлов и DNS-переключение реальных клиентов требуют отдельной приёмки.

Не блокируют 1.0: active-active, Kubernetes, marketplace плагинов, дополнительные
протоколы, выбор по скорости клиента, межпротокольная миграция, биллинг, новый GUI,
iOS-релиз. Поддержка и исправления безопасности продолжаются после 1.0.
