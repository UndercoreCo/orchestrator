# Конфигурация

По умолчанию `/etc/vpn-orchestrator/settings.json`. Можно передать `--settings`
перед подкомандой или `ORCHESTRATOR_SETTINGS`. Системные службы используют фиксированный
путь; `start/stop/restart` управляют именно этой установкой.

Обязательны `state_directory` и `backend_token_file` — абсолютные пути.
`schema_version` сейчас 1. Неизвестные поля, неверные типы и небезопасные границы
отклоняются. Ключи — приватные обычные файлы без symlink. Секретные значения
и исходные данные ошибки валидации не печатаются.

`nodes` поддерживается для однократного импорта старой установки. После инициализации
реестра источником истины становится SQLite, включая пустой список. Старые bootstrap
ключи после их ротации больше не требуются. Для новых установок `nodes` не нужен:
используйте `add server`. `admin_token_file` принят лишь для совместимости и игнорируется.

## Настраиваемая политика

Все значения целочисленные, длительности в секундах. В `policy` доступны:

| Путь | По умолчанию | Допустимо |
|---|---:|---:|
| agents.operation_timeout_seconds | 30 | 5–60 |
| agents.queue_timeout_seconds | 2 | 1–5 |
| agents.max_concurrent_requests | 16 | 2–64 |
| agents.max_concurrent_per_node | 4 | 1–32, строго меньше общего лимита |
| agents.max_pending_per_node | 8 | 1–64, не меньше узловой параллельности и меньше общего pending-лимита |
| agents.max_pending_requests | 64 | 2–256, не меньше общего лимита |
| agents.connect_timeout_seconds | 4 | 1–10 |
| agents.response_timeout_seconds | 12 | 1–15 |
| recovery.cooldown_seconds | 1800 | 60–86400 |
| recovery.reconcile_batch_size | 16 | 1–100 |
| selection.observation_workers | 4 | 1–16 |
| selection.observation_max_age_seconds | 30 | 1–300 |
| leases.offline_duration_seconds | 0 (выключено) | 0 либо 300–3600, только совместимый AWG-агент |
| leases.duration_seconds | 90 | 90–120 |
| leases.max_node_lease_seconds | 120 | 120–300 |
| leases.fence_grace_seconds | 125 | 125–600 |
| leases.heartbeat_workers | 64 | фиксировано 64 |

Старые настройки без новых полей принимаются с указанными значениями по умолчанию.
Новые ограничения меняют поведение при перегрузке и медленных ответах. Изменения применяются после
перезапуска API и рабочих процессов; не изменяйте настройки одного процесса отдельно.
Защитное ожидание равно максимуму ранее сохранённой границы и
`max(max_node_lease_seconds, offline_duration_seconds) + fence_grace_seconds`. Его минимальная
граница связана с watchdog и остановкой на узле; не является обычным timeout HTTP.

Периоды systemd timers, ограничения выполнения worker и версия протокола разрешений
остаются частью deployment contract. Их нельзя независимо сокращать через JSON.
HTTP timeout не означает, что мутация не произошла: автоматических транспортных
повторов с новым ключом нет. Незавершённое переключение продолжает ту же операцию.

Для клиента отдельно действуют порог обнаружения проблем и количество попыток.
Эти значения не объявляются управляемыми оркестратором, пока нет согласованного
контракта доставки политики приложениям.

## Проверка

`config validate --structure-only` проверяет структуру без чтения секретов.
`config validate` также проверяет приватные ключи и привязки журнала, не меняя БД.
`config validate --probe` дополнительно обращается к агентам для проверки идентичности.

## Автономное разрешение: кандидат 0.6.0

Параметр `policy.leases.offline_duration_seconds` ограничивает срок от выдачи
разрешения, а не добавляет время после потери управления. Например, 600 означает
не более 10 минут с последнего принятого разрешения. Свежесть управления остаётся
90 секунд по умолчанию. После её потери нельзя создать, продлить, заменить или
включить доступ; существующий туннель работает не дольше своего expires_at и
автономного разрешения. Полученный отзыв исполняется сразу.

По умолчанию настройка отсутствует/равна 0: используется прежний протокол v1.
Для включения все leased AWG-узлы должны объявлять `supported_versions: [1, 2]`
и достаточный `max_offline_seconds`. Неизвестная поддержка вызывает отказ,
молчаливого перехода на короткое разрешение нет. TrustTunnel этим изменением
не получает автономность. Готовность новых подключений проверяет свежесть,
а не оставшийся автономный срок.

Это локальный кандидат, не опубликованный релиз. Сначала требуется установка
согласованных agent/HTTP-компонентов и controller с прежними настройками; только
после проверки можно включить автономность. Старый controller не принимает новый
ключ настроек: до ручного возврата к 0.5.3 его нужно убрать, сохранив живой журнал
и записанное окно ожидания. Updater не выполняет ручное понижение версии.
Автоматический откат первого обновления проверяется с прежним файлом настроек;
не добавляйте новый ключ заранее в конфигурацию работающей старой версии.
