# Подключение своего backend

Backend отвечает за авторизацию, право на доступ, срок и свободный слот. Он
создаёт стабильный `device_id` и сохраняет ответный `connection_id`. Оркестратор
не проверяет пользовательские пароли и не является публичным API для приложения.

Нужны запущенный оркестратор и хотя бы один совместимый активный узел. Тесты
репозитория работают без узла; приведённая ниже последовательность — реальные
операции над доступом. Используйте отдельное тестовое устройство и отзовите его
после проверки. Ключ backend читайте из приватного файла и добавляйте в
`Authorization: Bearer …`; не передавайте его в командной строке или клиенте.
Для удалённого backend обязателен HTTPS, локально допустим loopback HTTP.

## 1. Узнать возможности

`GET /internal/v2/capabilities` возвращает доступные `protocols` и `export_formats`.
Выбирайте только протоколы, поддерживаемые и вашим VPN-клиентом, и сервисом.
TrustTunnel имеет экспериментальный драйвер, включаемый явно; его capability
нужно запрашивать у установленного сервиса. См. [матрицу поддержки](support.md).

## 2. Создать назначение

`POST /internal/v2/connections`:

```json
{
  "schema_version": 1,
  "device_id": "device-example-01",
  "name": "Test device",
  "expires_at": "2027-01-01T00:00:00.000Z",
  "capabilities": [{"protocol": "amneziawg", "configuration_version": 1}]
}
```

Дата приведена для примера: при реальном запросе передайте будущий оплаченный
или разрешённый срок. Ответ `Connection` содержит `connection_id`, `device_id`,
`node_id`, `protocol`, `state`, `expires_at` и `schema_version`.
Сохраните идентификаторы до следующего шага. Только `active` допускает использование
доступа; после ответа создания запросите конфигурацию с повторной проверкой состояния.

Если ответ потерян, повторите **тот же запрос для того же device_id**. Не создавайте
новое устройство и не меняйте срок в повторе первоначального запроса. Продление —
отдельная операция. Назначение не создаётся заново при каждом нажатии «Подключиться».

## 3. Получить параметры туннеля

`POST /internal/v2/connections/{connection_id}/configuration`:

```json
{
  "schema_version": 1,
  "device_id": "device-example-01",
  "capabilities": [{"protocol": "amneziawg", "configuration_version": 1}]
}
```

Ответ содержит `revision` и `configuration` с полями `protocol`, `version`,
`format`, `data`. Передайте данные соответствующему VPN-движку. Это секретный ответ:
не записывайте его в журналы, аналитику, публичный кэш или диагностический экспорт.
Ответ API подтверждает выдачу параметров, а не установление туннеля на устройстве.

Для стороннего клиента используйте `POST …/{connection_id}/export`:

```json
{"schema_version": 1, "device_id": "device-example-01", "format": "conf"}
```

`document` задаёт расширение, MIME-тип, кодировку и содержимое. QR возвращается
как PNG в base64. Файл — снимок параметров; после переноса на другой сервер его
может потребоваться импортировать снова. Формат выбирает драйвер оркестратора.

## 4. Продлить, проверить, отозвать

`POST …/{connection_id}/renew`:

```json
{
  "device_id": "device-example-01",
  "expires_at": "2027-02-01T00:00:00.000Z",
  "idempotency_key": "renewal-example-01"
}
```

Сохраните ключ операции до отправки. При потере ответа повторяйте прежний ключ и
тело; новый ключ предназначен для нового действия, не для сетевого повтора.

`GET …/{connection_id}?device_id=device-example-01` проверяет состояние.
`POST …/{connection_id}/disable` с `{"device_id":"device-example-01"}` отзывает
доступ. Таймаут отзыва не является подтверждением его завершения: повторите
операцию и проверьте состояние. `enable` не продлевает срок и не выдаёт новую оплату.

## 5. Восстановление

Передавайте в `POST …/{connection_id}/recover` прежнюю `expected_revision` вместе
с телом запроса конфигурации. Повтор той же ревизии не должен запускать новое
переключение. Сохраните новую ревизию успешного ответа.

Единичный сбой сайта не доказывает неисправность VPN. Клиент должен отличать
отсутствие сети, недоступность отдельного ресурса и проблему туннеля до recovery.
При `503 lease_waiting` продолжается безопасное ожидание отзыва; при `429
recovery_cooldown` нужно выдержать настроенную паузу. Не запускайте бесконечный цикл
и не создавайте новый device_id для обхода этих состояний.

Политика повторов: [ошибки](errors.md). Формальные тела и ответы:
[OpenAPI](https://github.com/UndercoreCo/orchestrator/blob/main/contracts/openapi.json). Совместимые маршруты v1 описаны отдельно
в [API](api.md); новым интеграциям они не нужны.
