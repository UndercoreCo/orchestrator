# Входящий API

API предназначен для доверенного backend, после проверки пользователя и права на
подключение. Все маршруты, включая health, требуют `Authorization: Bearer <token>`.
Backend-токен берётся из отдельного файла на сервере. Управление узлами
доступно локальному CLI и отдельной панели с `--manage`; `/internal/admin/*` больше не обслуживается. Внешний доступ — только через
HTTPS и ограничение источников; локально сервис слушает `127.0.0.1:8792`.
Все ответы имеют `Cache-Control: private, no-store`; тела и заголовки авторизации
не должны попадать в журналы reverse proxy и трассировки.

Самостоятельная [панель просмотра](panel.md) использует другой порт и собственный
ключ; её `/admin/v1/overview` не является маршрутом этого backend API.

Машиночитаемые модели: [JSON Schema](https://github.com/UndercoreCo/orchestrator/blob/main/contracts/orchestrator-connections.schema.json).
Версия URL `/internal/v2` и `schema_version: 1` — разные уровни версионирования.
`GET /internal/v2/capabilities` показывает реально включённые возможности.

Полный пример: [интеграция backend](integration.md). Статическая
[OpenAPI 3.1](https://github.com/UndercoreCo/orchestrator/blob/main/contracts/openapi.json) описывает v2, health и обзор узлов;
совместимые операции v1 остаются в этом руководстве. [Обработка ошибок](errors.md).

## Операции

`{id}` — стабильный `connection_id`, возвращённый сервисом.

| Метод и путь | Назначение / тело |
|---|---|
| `GET /v1/health` | Состояние процесса и версия релиза; не проверка всех узлов |
| `GET /internal/v1/metrics` | Метрики Prometheus и очередь из локального журнала, без запросов к агентам |
| `GET /internal/v1/nodes` | Узлы, протоколы (`protocol`), режимы, число назначений; не актуальный speed test |
| `POST /internal/v2/connections` | Создать или получить назначение: `DeviceRequest` |
| `GET /internal/v2/connections/{id}?device_id=…` | Состояние принадлежащего устройству подключения |
| `POST /internal/v2/connections/{id}/export` | Файл или готовый QR: `ExportRequest` |
| `POST /internal/v2/connections/{id}/configuration` | Получить параметры: `ConfigurationRequest` |
| `POST /internal/v2/connections/{id}/renew` | Продлить: `device_id`, `expires_at`, `idempotency_key` |
| `POST /internal/v2/connections/{id}/disable` | Отозвать: `device_id` |
| `POST /internal/v2/connections/{id}/enable` | Включить ранее отключённое: `device_id`; срок доступа не продлевается |
| `POST /internal/v2/connections/{id}/recover` | Восстановить: `RecoveryRequest`, текущая `expected_revision` |
| `POST /internal/v2/connections/{id}/switch` | Операторское переключение: `SwitchRequest`; не открывать клиентам напрямую |
| `POST /internal/v2/connections/{id}/replace` | Совместимость замены: `device_id`, `expected_external_id`, `expires_at`, `idempotency_key`, необязательный `allow_create` |

Пример создания (синтетические значения):

```json
{
  "schema_version": 1,
  "device_id": "device-example-01",
  "name": "MacBook",
  "expires_at": "2027-01-01T00:00:00.000Z",
  "capabilities": [{"protocol": "amneziawg", "configuration_version": 1}]
}
```

Создание возвращает `Connection`: идентификаторы подключения, устройства и узла,
протокол, состояние и срок. Получение `/configuration` требует тех же
`schema_version`, `device_id`, `capabilities`, без имени и срока. Ответ дополнительно
содержит `revision` и `configuration` с `protocol`, `version`, `format`, `data`.
`data` содержит секретный документ для VPN-движка. Не логировать его и не помещать
в URL, аналитику, диагностический экспорт или открытый кэш.

## Повторы и восстановление

Повтор создания одного устройства с совместимым протоколом использует прежнее
назначение. Продление и переключение имеют ключ идемпотентности. При сетевом
таймауте повторять тот же запрос и ключ, не создавать новое устройство.

`recover` использует ревизию, которую получил клиент. Повтор старой ревизии не
переключает устройство обратно. Между новыми переключениями действует ограничение
1800 секунд. Изменение узла сохраняет `connection_id` и `device_id`.

Если отзыв старого доступа ещё не подтверждён, переключение не считается
завершённым. Фоновый обработчик продолжает незавершённые операции. Для узла с подтверждённым коротким разрешением полный отказ API переводит
операцию в ожидание `503 lease_waiting`. Разрешение больше не продлевается;
после безопасного интервала операция продолжается в фоне или при повторе той
же revision. Узлы без leases по-прежнему требуют подтверждённого отзыва через API.
Перезагрузка управляющей машины начинает безопасное ожидание заново.

## Ошибки

Тело прикладной ошибки: `{"detail":"machine_readable_code"}`. Примеры:

| HTTP | Смысл |
|---|---|
| 401 | Нет действительного служебного токена |
| 404 | Подключение не найдено/не принадлежит указанному устройству |
| 409 | Конфликт состояния, ревизии, идемпотентности или требуется обновление клиента |
| 410 | Доступ истёк/недоступен в запрошенной операции |
| 413 / 422 | Слишком большой или неверный запрос |
| 429 | Пауза между восстановлениями, `recovery_cooldown` |
| 503 | Нет подходящего узла, узел недоступен или идентичность не подтверждена |

Точный код зависит от операции. Нельзя трактовать любой 503 как доказательство
блокировки провайдером или повторять мутацию с новым ключом без проверки состояния.

## Совместимость v1

Сохранены `/v1/clients`, `/v1/clients/{id}` и операции
`configuration`, `amnezia`, `renew`, `replace`, `enable`, `disable` для существующего
backend. Новый код должен использовать контракт v2. Поле `mode: pilot` в старом
health сохранено ради совместимости и не определяет способ развёртывания.


## Локальное управление узлами

Административные HTTP-маршруты удалены. Backend заказчика не имеет ключа управления
оркестратором. Используйте `undercore-orchestrator add/update/check/restore server`
и `list servers`, описанные в [быстром старте](quickstart.md).

Полный каталог машинных ошибок: `contracts/errors.json`; CI проверяет наличие
каждого кода в каталоге. Формат ошибок v1/v2 остаётся `{ "detail": "code" }`.
Новая асинхронная операция с ответом 202 и новая оболочка ошибок требуют отдельной
версии контракта; в этом рефакторинге они намеренно не вводятся.

## Точечный поиск для backend v1

`POST /v1/clients/lookup` принимает только `external_id` (1–100 символов
`A-Za-z0-9_-`) и `device_id: "account-v1"`. Требуются тот же служебный Bearer-токен
и HTTPS; ответ имеет `Cache-Control: private, no-store`.

Ответ: `{"clients": []}` либо `{"clients": [client]}` с прежней моделью v1.
Поиск использует уникальный индекс журнала назначений, не полный список клиентов.
Если назначения нет, VPN-узлы не опрашиваются. Если оно есть, проверяется только
закреплённый узел; выключенный доступ остаётся выключенным. Незавершённое создание
после потери ответа восстанавливается на прежнем узле с той же identity.
Таймаут, конфликт владельца/узла и 503 не превращаются в пустой результат.
Подтверждённый 404 отсутствующего peer сохраняет прежнюю семантику поиска v1.
Операция не создаёт назначение, не продлевает доступ и не выдаёт секретный документ.

Старый `GET /v1/clients` сохраняется для совместимости. Backend должен включать
новый маршрут после обновления оркестратора. Автоматического fallback к полному
списку при отказе нового маршрута нет.

## Экспорт для сторонних приложений (0.3.4)

`POST /internal/v2/connections/{id}/export` получает `schema_version: 1`,
`device_id`, `format` (`conf`, `amnezia-vpn` или `qr`). Доступные значения публикует
адаптер в `GET /internal/v2/capabilities` → `protocols[].export_formats`.
Оркестратор не выбирает другой протокол при неподдерживаемом формате.

AmneziaWG предоставляет `.conf`, `.vpn` (содержимое `vpn://`) и QR в PNG.
По умолчанию QR кодирует `.conf` для AmneziaWG. Для AmneziaVPN передайте
`format: "qr", qr_content_format: "amnezia-vpn"`; для обычного файла эта опция
не используется. Два QR не взаимозаменяемы: сканирующее приложение должно
понимать выбранное представление.

Ответ `ConnectionExport` содержит идентификаторы, протокол, состояние, срок и
`document`: `format`, `media_type`, `extension`, `encoding`, `data`.
Файлы передаются как `utf-8`, готовый PNG — как `base64`. Backend проверяет
принадлежность и срок, возвращает файл/картинку пользователю; не строит VPN-документ
и не определяет его содержимое. Безопасное имя загрузки может задавать backend.
Экспорт использует существующее назначение и не занимает дополнительный слот.

Проверяются владелец устройства, состояние peer, срок, запрет выдачи, lease и
незавершённое переключение. Неверное устройство — 404, неподдерживаемый формат —
422 `unsupported_format`, неактивный доступ — 410 `access_unavailable`.
Слишком большой для одного QR документ — 422 `qr_unavailable`, без обрезки.
Предел: 64 KiB файла, 2331 байт QR (byte mode, ECC M). Все данные остаются в памяти;
в журнал, SQLite или URL не попадают. Ответы `private, no-store`.

Для WireGuard предусмотрена отдельная политика экспорта только `.conf` и QR;
полноценного WireGuard-драйвера lifecycle пока нет, runtime его не рекламирует.
TrustTunnel публикует capability только при `experimental_trusttunnel: true`;
параметры выдаются через `/configuration` как `trusttunnel-toml`. Файловые экспорты
AWG ему не приписываются. Требуется совместимый managed-agent; см. [матрицу](support.md).

Скачанный файл/QR — снимок параметров. В стороннем клиенте он не обновится сам
при переносе подключения на другой узел: нужно повторно импортировать экспорт.
Собственные клиенты продолжают использовать `/configuration` и recovery.

## Корреляция и диагностика

Ответы содержат сгенерированный сервером X-Request-ID; входной заголовок с этим именем
не используется. Передайте идентификатор оператору при сбое, не пересылая секретный
документ. Подробнее: [диагностика и метрики](observability.md).

Локальная перегрузка возвращает `503 connection_busy`; общий бюджет операции —
`503 node_unavailable`. Это не доказательство отказа VPN-узла.
[Лимиты и правила повторов](runtime-limits.md).


### Lookup by canonical device identity

`POST /internal/v2/connections/lookup` accepts `{"device_id":"device-example"}`
and returns `{"connections":[Connection]}`. It requires the same backend token,
returns metadata only, and never provisions, renews or exports credentials.
An unknown device returns an empty list. Upstream uncertainty is an error,
not evidence that the assignment is absent. This endpoint also supports the
experimental TrustTunnel adapter without routing it through AWG v1 endpoints.

## Статистика трафика

`POST /internal/v2/usage` передаёт исходные счётчики без агрегации.
[Контракт, границы и ограничения](traffic.md).

Обзор узлов содержит `protocol` из реестра каждого узла. Это добавочное поле ответа;
потребители прежних выпусков должны допускать его отсутствие и не определять протокол
по имени узла. API не возвращает адреса управления и ключи.
