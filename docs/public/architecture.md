# Архитектура

Оркестратор — самостоятельный модульный сервис. Backend заказчика решает, имеет
ли пользователь доступ, резервирует слот и передаёт device_id и срок. Оркестратор
управляет техническим назначением. Он не хранит пароли пользователей или платежи.

## Карта кода

- `bootstrap.py` собирает настройки, журнал, реестр, агент и драйверы.
- `domain/` содержит типы узлов, конфигураций, версий и ошибки.
- `application/execution.py` определяет общий бюджет прикладной операции;
  infrastructure использует его для ожиданий HTTP и блокировок.
- `application/telemetry.py` задаёт порт наблюдения и контекст корреляции;
  `infrastructure/observability.py` реализует JSON-события и Prometheus.
- `application/` содержит сценарии выдачи, отзыва, переключения, восстановления,
  управления узлами и коротких разрешений. `ports.py` задаёт контракты драйвера и lease transport;
  `repository_ports.py` — узкие интерфейсы журналов и хранилища секретов.
- `interfaces/http/` проверяет служебную авторизацию и преобразует вход/выход v1/v2.
- `interfaces/cli/` разбирает команды и приватные файлы оператора.
- `infrastructure/drivers/` содержит общий NodeHTTP, рабочий драйвер Amnezia-agent
  и экспериментальный адаптер TrustTunnel, включаемый только явным experimental_trusttunnel.
- `infrastructure/sqlite/` владеет журналом, транзакциями, миграциями и блокировками.
- `config/` задаёт чистые модели настроек и политики. Загрузка файлов, секретов
  и сохранённого реестра находится в `infrastructure/settings.py`; сборка — в bootstrap.
- `infrastructure/systemd.py` управляет фиксированным набором служб без shell.

Пакет `orchestrator/` остаётся в корне, чтобы существующие source releases и
systemd entry points продолжали работать. `pyproject.toml` позволяет собрать wheel
и установить CLI обычным pip. Перенос в `src/` сам по себе не улучшает границы,
поэтому не требует миграции всех установленных путей.

## Управление

Локальный CLI вызывает сценарии работы с узлами и использует общие межпроцессные
блокировки. Запускается от того же системного пользователя, что служба.
Админка сайта не управляет реестром или таймаутами. Административный HTTP API удалён.
Обычный backend API работает независимо от наличия какой-либо админки.

## Постоянное состояние

SQLite содержит назначения, ревизии, незавершённые переключения, реестр серверов,
разрешения и отложенный отзыв. Конфигурации туннелей и приватные VPN-ключи не
сохраняются: только digest документа. Секреты агентов лежат в отдельных 0600-файлах.

Миграции собраны в одном модуле; сохранены прежние таблицы и их семантика.
Прикладные сценарии работают через `Journal`, `SwitchJournal`, `LeaseJournal` и
`InventoryJournal`. SQL находится только в инфраструктуре. Репозитории возвращают
типизированные записи, а не соединения SQLite или курсоры.

`SwitchRepository.complete` одной транзакцией меняет назначение и завершает
переключение; резервирование цели учитывает остальные незавершённые операции.
Сценарий удерживает прежнюю межпроцессную блокировку через `Journal.lock` вокруг
локальных записей и обращения к узлу. Извлечение SQL не сокращает область блокировки.
Время выдачи lease сохраняется до сетевого запроса; неизвестный результат не
разрешает досрочно считать предыдущий доступ отозванным.

Версия схемы и порядок обновления описаны в [совместимости](compatibility.md).
Миграции сохраняют назначения, ключи повторяемости и незавершённые операции.

## Гарантии жизненного цикла

Одна операция имеет стабильную идентичность. Потеря ответа не разрешает создать
другое назначение. Отзыв источника должен быть подтверждён или обеспечен
проверенным механизмом ограниченного разрешения. Незавершённая операция закреплена
за целевым узлом и восстанавливается после перезапуска. Нельзя произвольно выбрать
третий сервер после таймаута и оставить неизвестное состояние на втором.

Экспериментальный TrustTunnel-драйвер подключается явно и использует собственную
схему конфигурации. Для нового протокола обязательны драйвер, гарантии жизненного
цикла и тесты; имя в enum не делает протокол доступным.

## Границы этого выпуска

Форматы v1/v2 не меняются. Не добавлены автоматические speed tests, пользовательская
геолокация, многоарендность, новый 202 API или цепочки перебора нескольких серверов.
Число автоматических попыток в нативном приложении остаётся его политикой.
Вынесены только реально действующие настройки; неиспользуемых переключателей нет.

Старый лабораторный runtime и его 32 теста удалены. Рабочие тесты с закреплённым
агентом сохранены; добавлены проверки CLI, пустой установки, политики и реестра.

## Направление зависимостей

Целевые правила фиксируются в `contracts/architecture.json` и проверяются командой
`python scripts/check_architecture.py`. Проверка читает AST исходников, не запускает
приложение и не загружает настройки или секреты.

| Слой | Разрешённые внутренние зависимости |
|---|---|
| domain | Только domain; Pydantic разрешён для существующих моделей контрактов |
| application/ports, repository_ports, telemetry и execution | domain и другие определения ports |
| application | domain, ports, application, модели config/policy |
| config/policy | Только собственные модели политики |
| config | config/policy, domain и собственные модули конфигурации |
| infrastructure | domain, ports, config/policy и собственные реализации |
| interfaces/http | application, ports, domain, version и HTTP-модули |
| interfaces/cli | Прикладные операции, bootstrap, конфигурация, инфраструктура и CLI-модули |
| bootstrap | Собирает конкретные реализации и HTTP-приложение |
| version | Не зависит от остальных runtime-модулей |

CLI сейчас совмещает адаптацию команд и локальные операции установки, резервного
копирования и systemd. Поэтому его доступ к инфраструктуре явно разрешён. HTTP
обработчик такого доступа не имеет. Доменные модели и прикладной слой не импортируют
HTTP/SQL-фреймворки. Policy-модели используют Pydantic; бизнес-сценарии от него не зависят.

Совместимые корневые модули перечислены отдельно. Они служат входом для старых
установок; импортировать их из новых слоёв в обход правил нельзя. Новые модули в
корне нужно явно классифицировать. Проверяются абсолютные, относительные, локальные
и TYPE_CHECKING-импорты. Прямые вызовы __import__/importlib.import_module запрещены:
динамические плагины сейчас не часть контракта.

Это статическая проверка объявленных зависимостей. Она не анализирует произвольное
исполнение Python, SQL-строки, вызовы через переданные объекты или циклы внутри слоя
и не является песочницей безопасности. Сохранение транзакций проверяется отдельно
сценариями жизненного цикла.

## Проверяемые границы

Этап 4 устранил все 20 исключений первого этапа: `exceptions` теперь пуст.
Новые зависимости проверяются по общим правилам; расширять список разрешений
для обхода ошибки запрещено. Отдельный тест не допускает прямых вызовов SQL
и открытия базы в application.

`bootstrap.build_gateway` связывает журнал, драйверы, lease transports и ресурс
закрытия HTTP-пула. `build_registry` передаёт хранилище файлов секретов через
`Credentials`. Прикладной сценарий не создаёт AgentAPI и не читает ключ с диска.
CLI читает входной файл до вызова сценария управления узлом.

`LeaseTransport` переводит проверенное состояние агента в `LeaseObservation`
и принимает `LeaseGrant`. Прикладное управление lease не знает HTTP-путей,
JSON-полей или версии Amnezia-agent. Реализация Amnezia находится в
`infrastructure/drivers/amnezia_leases.py`; новый протокол получает свой адаптер.
Отсутствующий адаптер не даёт молча включить lease.

`domain/records.py` определяет записи журналов и результаты драйвера. Mypy проверяет
доменные модели, порты, реестры драйверов, SQLite-реализации, файловое хранилище
секретов и два адаптера Amnezia. `scripts/check_types.py` проверяет соответствие
конкретных реализаций портам. Это покрытие границ, не строгая типизация всего проекта.

Модели RenewRequest/ReplaceRequest/DeviceOperation используются и при HTTP-декодировании,
и при генерации OpenAPI. Прежние маршруты и статусы ошибок сохраняются.

## Сценарии и контракт изменений

- [Идентификаторы, состояния и гарантии жизненного цикла](lifecycle.md).
- [Версии, обновления и совместимость](compatibility.md).
- [Границы доверия и секретные данные](security.md).

Панель просмотра запускается отдельным процессом `panel`: HTTP-интерфейс зависит
от порта `PanelReader`, SQLite-реализация открывает согласованный read-only снимок.
Bootstrap не создаёт сервис выдачи туннелей, не загружает секреты агентов и не запускает
миграции. Безопасные события API/worker поступают через ограниченный файловый EventTail.
В браузер передаются только модели `domain/panel.py`.
Клиентский backend API не становится административным; ключ панели отдельный.
Опциональный режим `--manage` использует `application/administration.py` вместе с CLI.
Порты OperatorJournal и PolicyEditor скрывают отдельный SQLite-аудит и атомарную запись
настроек. Намерение фиксируется до команды; неизвестный исход требует сверки.
Основная схема VPN-журнала не меняется. [Запуск и контракт](panel.md). Экспериментальный TrustTunnel-драйвер уже использует эти границы;
публичная поставка его узлового runtime остаётся отдельным этапом.
