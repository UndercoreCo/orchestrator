# Совместимость и изменения контракта

## Независимые версии

| Версия | Что описывает |
|---|---|
| `VERSION` / версия пакета | Выпуск программы и механизм обновления |
| `/v1` и `/internal/v2` | HTTP-контракт для доверенного backend |
| `schema_version` | Структуру документа запроса/ответа |
| `configuration.version` | Формат параметров конкретного VPN-движка |
| `revision` | Изменение параметров конкретного подключения |
| Версия схемы SQLite | PRAGMA user_version: 0 — прежний журнал, 1 — текущая версия |

Изменение версии пакета не означает смену HTTP-контракта. Имя протокола в модели
не подтверждает поддержку: backend и клиент сверяются с capabilities. Реализован AmneziaWG; TrustTunnel доступен экспериментально с явным флагом
`experimental_trusttunnel`. Это не означает готовности публичного установщика узла.
[Матрица поддержки](support.md).

## Требования к изменениям

- Сохранять идентификаторы, смысл повторов, статусы HTTP и машинные коды ошибок.
- Рассматривать новый обязательный параметр, новый enum, изменение значения по
  умолчанию или формата конфигурации как потенциально несовместимое изменение.
- Даже добавление необязательного поля требует проверки: часть моделей строго
  отклоняет неизвестные поля. Не считать расширение автоматически безопасным.
- Изменение оболочки ошибок, асинхронный ответ 202 или другая семантика create
  требуют отдельного контракта и плана перехода потребителей.
- Обновлять реализацию, схемы, примеры и контрактные тесты вместе. Генерация OpenAPI
  и проверка актуальности уже включены в CI; модели renew/replace/enable/disable уже общие для runtime и OpenAPI.
Оставшиеся описания ответов и legacy create/lookup проверяются контрактными тестами.

Legacy v1, корневые совместимые Python-импорты, CLI и systemd entry points остаются
действующими. Новые интеграции используют v2. Удаление старой точки входа требует
описанной замены, переходного выпуска и проверки реально используемых потребителей.
Фиксированный срок поддержки старых веток пока не объявлен.

## Обновление хранения

Схема имеет независимую версию `PRAGMA user_version`. Первая нумерованная миграция
принимает известные прежние структуры и атомарно создаёт недостающие таблицы,
заполняет device_id/binding_key прежним external_id и фиксирует версию 1. Данные
назначений, операций, запретов и leases сохраняются. Ошибка откатывает и DDL, и версию.
Запуск с будущей версией, повреждённой текущей схемой или чужой базой запрещён.

| Входной журнал | Результат |
|---|---|
| Пустая установка | Схема 1, без назначений и без автоматически добавленных серверов |
| 0: исходные assignments без device/protocol/revision/binding | Добавление полей, сохранение connection_id/remote_id, заполнение стабильных идентификаторов |
| 0: назначения и switches | Добавление таблиц leases и реестра, сохранение незавершённой цели |
| 0: leases/access_cache/retired_bindings | Сохранение sequence, fencing и denied; добавление реестра |
| 0: полный реестр предыдущего выпуска | Сохранение ревизий реестра и назначений, фиксация версии 1 |
| 1: текущая схема | Проверка структуры; повтор не изменяет данные |
| Новее 1 или повреждённая схема | Отказ до миграции, без автоматического исправления |

Матрица относится к проверенным структурам, а не к любому форку с таким же номером
релиза. `tests/test_storage_upgrade.py` проверяет эти варианты и атомарный отказ.

`contracts/storage.json` задаёт min_read/max_read/write и попадает в release manifest.
CI сверяет его с миграциями; сборщик читает контракт из того же Git-коммита, что и код.
Историческое `journal_schema: 2` в release.json означает поддержку leases и не является
номером user_version. Старые релизы без storage допускаются только для добавочного
перехода 0→1; проверка lease-aware rollback по-прежнему обязательна.

Updater проверяет совместимость отката до остановки процесса, репетирует миграцию
на копии базы и повторяет репетицию на финальном снимке после остановки всех writers.
При ошибке проверки здоровья возвращает код/units, сохраняя актуальный журнал.
Если живая схема неожиданно вышла за диапазон предыдущего кода, службы остаются
остановленными: автоматического восстановления старой базы нет.

Откат исполняемого кода возможен только при совместимой схеме данных. Нельзя
автоматически восстановить старую SQLite-копию поверх актуального журнала после
мутаций на VPN-узлах: база может потерять сведения о уже выданном или отозванном
доступе. Восстановление резервной копии — отдельная процедура сверки состояния.

## Административная панель

[Панель просмотра](panel.md) и `/admin/v1/overview` работают отдельным процессом
на `127.0.0.1:8793`, со своим ключом. Backend API на 8792 не меняется;
`/internal/admin/*` остаётся недоступным. Панель читает схему журнала 1 и отказывает
без миграций, если версия другая. Совместимость панели поставляется с её релизом.

Управление доступно локальному CLI и панели с `--manage`; они используют общие
команды и проверки. `operator.sqlite3` — отдельный журнал намерений версии 1,
который включён в backup. Основная схема VPN-журнала остаётся версии 1.
Старый код не использует аудит; записи после отката автоматически не повторяются.
Политики записываются атомарно в settings.json и применяются при новом запуске
процесса; текущие операции продолжают с прежней политикой.
Панель не переносит биллинг и пользовательскую авторизацию в оркестратор и не создаёт
зависимости от админки Undercore.

## Перед добавлением второго протокола

TrustTunnel проходит те же гарантии идентичности, повторов, истечения срока и
отзыва, что AmneziaWG. Его транспортные параметры и экспорты определяет адаптер;
форматы `.conf`, `.vpn` и QR нельзя автоматически приписывать новому протоколу.
Экспериментальный драйвер и стендовые проверки уже существуют; для поддерживаемой
поставки ещё нужны воспроизводимый агент и полная приёмка обновлений/отказов. Автоматическая межпротокольная миграция — отдельное изменение контракта,
не часть текущего переключения между узлами AmneziaWG.

## Проверенная совместимость с агентом

Контрактные тесты запускают закреплённый Amnezia-agent и вариант его HTTP API без
атомарного `/connection`: используется прежний fallback получения состояния и
конфигурации. Для leases отдельно требуются control_lease version 1, подтверждение
controller/sequence/deadline и прекращение доступа узлом. Отсутствие lease не
приравнивается к поддержке безопасного переключения после полного отказа сервера.
Эти тесты не заявляют совместимость со всеми версиями стороннего Amnezia API.
